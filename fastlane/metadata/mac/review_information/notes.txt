No account or sign-in is required. The app works fully offline.
Game Center is optional: leaderboards are only reported when the player is signed in.
The in-progress game is saved locally on the device and restored on the next launch.
Koi-Koi is a traditional Japanese card game played for points only; there is no wagering, in-app purchase, or real-money element.

Regarding Guideline 4.3(a) (previous macOS rejection):
- This is a native Mac app with Mac-specific functionality, not a repackaged mobile build: full hardware keyboard play (arrow keys, Return/Space, Esc) with an always-visible keyboard cursor, a three-column layout designed for resizable Mac windows, the scoreboard in the native window toolbar, and an optional translucent window backed by NSVisualEffectView.
- The app is my own original work, developed by me from scratch. The full source code is public at https://github.com/ngs/koikoi-swift . Its rules engine, computer opponent (four difficulty levels, the strongest using a determinized ISMCTS search), and user interface are all my own. I am also the author of an open-source Koi-Koi implementation in Go (go-koikoi, https://github.com/ngs/go-koikoi ), which shows the game logic is my own long-standing work.
- No purchased template, reskin, or third-party application code is used. There are no ads, no in-app purchases, and no third-party SDKs, and I have not submitted similar apps from any other account.
- The iOS and visionOS builds of this same app (same Bundle ID io.ngs.Koikoi, same version) are already approved; the macOS build shares their codebase and content.
- Koi-Koi is a traditional card game, so other apps for the same game naturally exist, but this implementation is entirely my own.
If a specific app was matched as similar, I would be grateful to know which one so that I can explain the differences.
